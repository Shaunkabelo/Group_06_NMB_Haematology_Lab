# Lab Manager requirements review — 7 October 2026

Scope: current subsytem/lab-manager code, checked-in SQL and read-only inspection of local order procedures. This does not certify the hosted database; its definitions may differ.

## Report requirement and ONP400 guidelines

Required report: total tests performed grouped by category over a selected date range.

Implemented using QuestPDF, not HTML printing:
- Descriptive title and laboratory name repeated on each page.
- Inclusive reporting period and generated date/time labelled SAST.
- Summary with total tests and categories represented.
- Scope explains completion-date selection and historical categories.
- Category breakdown sorted by count descending, then category name.
- Formatted counts, percentage shares and grand total.
- A4 pages, consistent typography, restrained greys, printable margins.
- Repeated table headings and Page X of Y footers.
- Empty reports retain title, dates, summary and a meaningful no-records message.
- Invalid/reversed dates and the maximum-date overflow case are rejected.
- Date choices are retained after server validation errors.

Verification: 76 regression checks passed, including PDF generation for 0, 3 and 150 categories. PDF extraction confirmed sorting, all 150 category rows appearing once, repeated headings, page numbers and text within margins across eight pages. Browser interaction and physical printing were not tested.

No stored procedure changes are required for this report layout. The existing sp_ManagerReport_TestsPerformedByCategory must be installed on the server. It counts LabTest records by CompletionDateTime, grouped by category, using an exclusive next-day upper bound. Confirm the team's completion timestamps use the intended reporting timezone; this change preserves their current interpretation.

## Report selection and consistency follow-up

The report page now offers tests by category, stock orders filtered by order date/current
status, and a current consumable stock snapshot with an optional near/below-reorder filter.
Stock snapshots do not apply historical dates. Existing repository procedures are reused.
Order report date/status filtering and stock's inclusive 110% threshold were verified
using generated PDFs. A ten-page order sample retained headings, page numbers and margins.

Screens/reports display Received and Partially Received while retaining the database's
Complete/Partially complete values for compatibility with existing procedures.
All eight manager-page Delete buttons now read Deactivate; action routes remain unchanged.

Normal ranges require both values and accept comma OR dot decimals consistently on the
client and server. They reject mixed separators, letters, exponents, more than four
decimal places and values exceeding DECIMAL(12,4). Maximum cannot be below minimum.
Negative values are supported because valid reference ranges can depend on the test.
Active supplier/category/sample checks, integer quantity bounds, report criteria and
cancellation reason length checks were added. Order numbers are generated on the server.
